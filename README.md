# omactl

One local CLI for installing, operating, verifying, backing up and updating an Open Marketing Agency instance. Runtime requirements: Docker Engine 24.0+ with Compose 2.24+ (Docker Desktop, OrbStack and Colima are supported through the active Docker context).

Start with the [user guide](docs/USER_GUIDE.md) for installation, the local demo, day-to-day commands, backups, recovery, updates, and troubleshooting.

```sh
bun install --frozen-lockfile
bun run typecheck
bun test test/unit
bun run build
```

Bun **1.4.4** is pinned in `package.json` and CI. `dist/` receives standalone Linux x64/arm64, macOS x64/arm64, and Linux musl x64/arm64 executables. `bun run build --current` builds only the local target.

Try the fixture apps on an isolated Docker instance:

```sh
docker build --build-arg APP_VERSION=1.0.0 -t omactl-testapp:1.0.0 fixtures/testapp
./dist/omactl-darwin-arm64 init --catalog catalog --http-port 18080
./dist/omactl-darwin-arm64 install --bundle notes-demo
./dist/omactl-darwin-arm64 verify --all --json
./dist/omactl-darwin-arm64 backup init --repository "$PWD/backups"
./dist/omactl-darwin-arm64 backup run --all
```

Choose the binary matching your platform. Source development uses `bun run dev -- <command>`. `OMA_HOME` defaults to `~/.oma`; use `--home` for another directory. Only one instance runs on a Docker daemon because app projects, volumes, and the edge network have fixed names.

Every command supports `--json`. Run changes with `--plan --json` to inspect steps first. Purge, restore, pruning, and binary rollback require a matching `--confirm` target. Configure a backup repository before updates or removal. Reinstalling an app with retained volumes recovers its original credentials from the final backup. Backups can use a local directory or S3-compatible storage; pass credentials through `backup init --env-file`.

```sh
omactl install testapp --plan --json
omactl status --json
omactl restore testapp --latest --confirm testapp --json
omactl history --limit 10 --json
```

The catalog contains Traefik and the purpose-built `testapp` / `testclient` fixtures. There are no production marketing apps. Add new apps as catalog folders following [CATALOG.md](docs/CATALOG.md). The maintenance agent contract is [AGENT.md](docs/AGENT.md); implementation and release details are in [ARCHITECTURE.md](docs/ARCHITECTURE.md). JSON Schemas are generated by `bun run schemas`.

Run the complete Docker acceptance suite on an isolated daemon, after building both fixture tags:

```sh
docker build --build-arg APP_VERSION=2.0.0 -t omactl-testapp:2.0.0 fixtures/testapp
OMA_E2E=1 bun run test:e2e
```

The suite refuses existing OMA containers, uses port 18080 and `.e2e/`, starts a local signed release server, and cleans up its own containers/volumes. It includes all 16 scenarios from the build spec. Without `OMA_E2E=1`, Docker tests are skipped.

For production releases, configure `OMA_RELEASE_PUBLIC_KEYS` before building, then `OMA_RELEASE_PRIVATE_KEY` and `OMA_RELEASE_ASSET_URL` for `bun run release`. No production signing key was supplied with the spec; default builds refuse network releases. Test keys are never trusted by default. Release publication and real-reboot CI need repository credentials and cloud variables; see the workflows in `.github/workflows/`.
