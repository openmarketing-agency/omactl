# Architecture

omactl is a Bun-compiled TypeScript CLI. `src/cli` parses commands and validates envelopes; `src/core` owns instance state, mutation plans, exclusive locks, redaction, operation journals, and isomorphic-git history. `src/docker` is the Docker/Compose process boundary. Catalog, apps, routing, backups, releases, and platform adapters remain separate modules. Dependencies are pure JavaScript: Commander for parsing, Zod for schemas, YAML for configuration, and isomorphic-git so no host Git is required. AJV, TypeScript, Bun types, and Prettier are development-only pure JavaScript dependencies.

An instance lives at `$OMA_HOME`, defaulting to `~/.oma`. App Compose projects always use the catalog, generated, and optional override layers in that order. Catalog files are replaced on updates; overrides survive. Databases and internal services remain on the project's default network; the main service joins the shared external `oma_edge` network. Traefik uses a named-volume file provider and never sees the Docker socket. Config and routes are streamed as tar archives through pinned helper containers.

Mutations receive an `op_<UTC>_<random>` identifier, exclusively acquire `state/lock`, execute timed journal steps, commit tracked config through isomorphic-git, and release the lock. Contenders wait up to `--lock-timeout`; dead owners can be reclaimed. Plans and missing destructive confirmations never create instance state. Read commands do not take the mutation lock. Verify records last-check state and therefore is journaled.

Secrets are generated with cryptographic random bytes, saved with mode 0600, injected through environment files or hook stdin, and redacted recursively from all logs, errors, journals and ordinary output. A hook output is registered for redaction before its stdout is journaled. Only `credentials` intentionally exposes values. Config history excludes `.env`, `secrets/`, `state/`, `logs/`, and `catalog/`.

Restic runs in a pinned multi-platform container. File-policy volumes mount read-only during backup; app configuration is streamed into an ephemeral staging volume. Local repositories use a dedicated repository bind mount; app data/config never use host mounts. Remote credentials are passed only by `--env-file`. Non-pruning restic operations use `--no-lock`, allowing repositories without delete permission; the per-instance mutation lock serializes local writers. Use separate per-instance repositories or coordinate external writers. Central-policy instances cannot prune. Retention groups snapshots by host and paths so operation/reason tags do not prevent aging out snapshots; recent pre-update snapshots are excluded from deletion.

Updates verify Ed25519 signatures over exact channel bytes, check asset SHA-256 hashes, safely extract and validate the catalog, then swap it atomically. Apps update one at a time, each with a pre-update snapshot. A failed update restores the previous tracked Compose definition from Git, preserves overrides, restores data and verifies. Exit 6 means the old version works; exit 7 means rollback failed and the app is `needs_human`.

Public release keys are compiled in via `OMA_RELEASE_PUBLIC_KEYS`, a JSON array of PEM public keys passed to the build. The repository has no supplied production trust root, so default builds fail closed on downloaded releases. `init --catalog` supports local development. `fixtures/keys/` contains a deliberately public **test-only** keypair; acceptance tests compile their own binaries trusting it. Never include that key in production builds.

`src/platform` contains OS detection, support tiers, default paths, doctor probes, systemd/launchd integration, and the self-update smoke-test exception to the Docker-only process rule. Scheduled jobs call a hidden in-process dispatcher so no host shell is needed. A source run cannot self-update Bun; use a compiled executable. Scheduler installation should likewise use the compiled binary.

Channel files are at `/channels/<stable|canary>.json` with detached `.sig` files. Explicit releases are at `/versions/<version>.json` and `.sig`. Signatures can be raw 64-byte Ed25519 values or base64 text. Catalog archives have no enclosing directory. Heartbeats are optional and failures only produce warnings.
